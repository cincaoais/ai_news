# Implementation Plan: Daily AI News Bot

Date: 2026-07-31 · Phase 2 of system-builder · Inputs: `docs/00-BRIEF.md`, `docs/01-RND.md`

## Goal recap

Every morning ~8:00 AM MYT, a short 5–8-item news digest for the active topic profile lands
in the user's Telegram, generated by Claude under the user's subscription (no LLM API key),
scheduled fully in the cloud, free to run. Success: accurate, non-repetitive, arrives
unattended; profile switchable via config; failures notify rather than vanish.

## Architecture overview

```
                      ┌────────────────────────── GitHub repo (private) ──────────────────────────┐
                      │  config/profiles/*.yaml   CLAUDE.md (editorial rules + output schema)     │
                      │  scripts/*.py             RUNBOOK.md (daily procedure)   state/seen.jsonl │
                      └───────────────────────────────────┬───────────────────────────────────────┘
                                                          │ cloned each run
        ┌─────────────────────────────────────────────────▼──────────────────────────────────────┐
        │  SCHEDULER (choice is config, not code):                                               │
        │   PRIMARY: Claude Code Routine — daily 8:00 MYT, model=Sonnet, network=Custom/Full     │
        │   FALLBACK: GitHub Actions cron 2347 UTC + claude -p (CLAUDE_CODE_OAUTH_TOKEN)         │
        └────────────────────────────────────────────────────────────────────────────────────────┘
                 daily run, per RUNBOOK.md:
    (1) fetch_news.py: profile feeds + Google News fallback + Yahoo chart API (browser UA)
        → freshness filter → canonicalize URLs → drop seen → work/candidates.json (indexed)
    (2) Claude (the ONLY LLM step): read candidates + state/last_digest.md
        → select 5–8 by INDEX, write summaries → work/selection.json (schema in CLAUDE.md)
    (3) build_and_send.py: validate selection (indices exist, no URLs from model)
        → build HTML (script attaches real URLs) → split ≤3500 → sendMessage w/ retry
    (4) update_state.py: append sent URLs/headlines to state/seen.jsonl (30-day prune),
        rewrite state/last_digest.md → git commit + push (pull-rebase + one retry on reject)
    on any step failure → notify_failure.py sends alert to the Telegram chat
    ALERT CHANNELS ARE TWO: (a) Telegram notifier for in-pipeline failures; (b) a separate
    watchdog workflow (Slice 6) that fails — triggering GitHub's native failure e-mail —
    when state/ hasn't been updated in >26h. (b) covers the classes (a) cannot: Telegram
    creds dead, or the Routine never ran at all. Residual risk: none silent by design.
```

Design laws (from RND, non-negotiable):
- **The model never types a URL.** Items referenced by index; scripts own all URLs. (01-RND §Theme C)
- **RSS-only must suffice.** WebSearch/WebFetch/connectors are enrichment, never load-bearing. (§Theme B)
- **Artifact-existence is the success signal**, never exit code 0 alone. (§Theme B)
- **Every feed fetch checks freshness** (newest pubDate), sends a browser UA. (§Theme D)

## Tech stack & justification

| Choice | Justification (RND citation) |
|---|---|
| Python 3.11+, deps only `feedparser`, `pyyaml`, `requests`, `pytest` | Free, runs identically on dev/Routine/Actions; battle-tested RSS parsing beats hand-rolled XML (§prior art: every mature repo uses a parser lib) |
| Telegram via raw HTTPS + HTML parse mode | Official docs confirm no library needed; HTML = 3 escape chars vs 20+ for MarkdownV2 (§Theme E) |
| Claude Code Routines as primary scheduler | Only first-party, ToS-clean, PC-off, subscription-auth scheduler; Sonnet-selectable (§Theme A). Connector enrichment (FMP/Bigdata) is possible on this path but **deferred to v2** — no v1 slice builds it |
| GitHub Actions + `claude setup-token` fallback, bare CLI not action-wrapper | Action wrapper blocks WebSearch/WebFetch (action#690); token documented 1-year; `--bare` incompatible with OAuth token (§Theme A/B) |
| State as flat files committed to repo | Standard pattern in all 3 Claude-CLI prior-art repos; doubles as 60-day-disable keepalive (§Theme C/A) |
| Feeds per 01-RND §Theme D verified list only | Live-verified 2026-07-31; Reuters/Kitco/Stooq/ESPN/Star/Edge dead or blocked — excluded by evidence |
| CLAUDE.md carries editorial rules + JSON schema | Auto-loaded by Claude Code in cloud session; avoids giant prompt strings (regrow1123 pattern, §prior art) |

## Milestones & vertical slices

### User checkpoints (batched; nothing else blocks on the user)

- **Checkpoint A — before Slice 2 live tests (~3 min):** create bot via @BotFather, send it
  `/start`, then run `scripts/get_chat_id.py` (Slice 2 deliverable) to print the chat_id.
  Slice 2 unit tests don't need this; its live-send acceptance does.
- **Checkpoint B — before Slice 4 (~7 min):** create/push the private GitHub repo (commander
  attempts via `gh` first; user only if unauthenticated); run `claude setup-token` and store
  as repo secret with `TELEGRAM_*`; grant Claude Code on the web repo access (`/web-setup`).
- **Checkpoint C — during Slice 5:** confirm Routine env settings in the web UI (network
  access, env vars) if the CLI path can't set them.

### Milestone 1 — Pipeline works end-to-end on the dev machine

- **Slice 1 — Config + fetcher (data in)**
  - Delivers: `fetch_news.py` runnable via `python scripts/fetch_news.py` → writes
    `work/candidates.json` for the active profile with live feed data; switching
    `active_profile` in `config/config.yaml` changes sources with zero code edits.
    All 4 profiles authored (finance_metals default, sports, entertainment, malaysia_politics)
    using **exactly the sources and YAML schema inlined in "Profile data & schema" below** —
    no guessed URLs; anything not listed there requires live verification first.
  - Tasks (one subagent): repo skeleton per File layout; `lib/feeds.py` (fetch w/ browser UA +
    10s timeout, parse, per-feed freshness check → stale feeds logged + skipped, item lookback
    filter); `lib/market.py` (Yahoo chart API, UA header, graceful skip on failure);
    `lib/state.py` (URL canonicalization: strip utm_*/fragments, host lowercase; seen-hash
    load); `fetch_news.py` orchestration → indexed candidates.json; bootstrap `work/` and
    `state/` with `exist_ok` + empty `seen.jsonl` on first run; **thin-news policy**: if
    post-dedup candidates < min_items, widen lookback ×2 (local re-filter) once; if still
    < 3, proceed anyway and tag candidates.json `"thin_news": true` (digest still sends with
    a "quiet news day" note — the daily message is the heartbeat, never skipped); 0 candidates
    → exit nonzero (feeds down) → notifier path; profiles; fixtures; tests.
  - Acceptance criteria: candidates.json contains ≥10 indexed items for finance profile on a
    normal news day; each item has {index, title, source, url, published, snippet}; market
    block present with ^GSPC, ^IXIC, GC=F, USDMYR=X when profile enables it; seen URLs
    excluded; stale feed (fixture frozen >48h) skipped with warning, not crash; dead feed
    (connection error) skipped, not crash; run completes with ≥1 live feed down; thin-news
    fixture (2 candidates) → widened lookback then `thin_news` flag, no crash;
    all-feeds-down fixture → nonzero exit.
  - Test gate: `pytest tests/test_feeds.py tests/test_state.py tests/test_market.py` green —
    parsing fixtures, freshness filter, canonicalization table, seen-dedup, UA header
    asserted, market fallback; plus one live smoke run writing real candidates.json.
  - Depends on: none. Parallelizable with: none (sequential mode).

- **Slice 2 — Telegram out + state (data out)**
  - Delivers: `build_and_send.py` + `update_state.py` + `notify_failure.py`; given
    candidates.json + a hand-written selection.json → valid HTML digest printed in
    `--dry-run`, sent live when `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` env vars exist.
  - Tasks (one subagent): `lib/telegram.py` (escape `<>&`, block-based split ≤3500,
    `link_preview_options is_disabled`, retry: 429→retry_after, 5xx→backoff, 4xx→raise);
    `scripts/get_chat_id.py` (calls getUpdates, prints chat_id — Checkpoint A tooling);
    **same-day guard**: before sending, if `state/last_digest.md` date == today for this
    profile → abort with notice unless `--force` (prevents duplicate digests from
    overlapping schedulers/manual runs); push resilience in `update_state.py`
    (`git pull --rebase` + one retry on rejected push, then notifier);
    validation (every selected index exists in candidates; summaries non-empty; reject any
    `http`/`www` substring in model text fields); digest formatting (header w/ date+profile,
    per item: linked bold headline → 1–2 line summary; market snapshot line); state append
    w/ 30-day prune + last_digest.md rewrite; failure notifier (plain text, no HTML).
  - Acceptance criteria: dry-run output is valid Telegram HTML under limits for 1-item and
    12-item fixtures; selection referencing index 99 → hard error naming the index; summary
    containing a URL → hard error; state file grows by exactly the sent items and prunes
    >30-day rows; notifier works with malformed-HTML-proof plain text; second send attempt
    same day aborts without `--force`; rejected push (fixture repo) recovers via
    rebase-retry; `get_chat_id.py` prints chat_id from a mocked getUpdates payload.
  - Test gate: `pytest tests/test_telegram.py tests/test_validation.py tests/test_state_update.py`
    green — escaping, splitting boundaries (no mid-tag split), retry paths (mocked HTTP),
    validation rejections, prune logic, same-day guard, push-retry.
  - Depends on: Slice 1 (candidates format).

- **Slice 3 — Claude editorial step (intelligence)**
  - Delivers: `CLAUDE.md` (editorial rules: straight-to-the-point tone, why-it-matters
    angle, market-impact lens for finance profile, soft-dedup instruction reading
    last_digest.md, hard rules: 5–8 items, indices only, output schema, English) +
    `RUNBOOK.md` (exact step sequence + failure handling) + `run_digest.py` (local/CI
    wrapper: fetch → `claude -p` subprocess w/ `--output-format json --model sonnet
    --max-turns 20 --permission-mode dontAsk --allowedTools "Read,Write,Bash"` + timeout →
    verify selection.json exists + schema-valid → send → state; any failure → notifier).
  - Tasks (one subagent): author CLAUDE.md/RUNBOOK.md; wrapper w/ subprocess pattern from
    RND (check artifact, scan result text for "hit your...limit"); JSON-schema validation of
    selection.json with a **prose-tolerant extractor** (model may wrap JSON in fences/prose
    per RND — strip to first `{`…last `}` before parsing; fixture test for prose-prefixed
    file); one retry with the validation error appended to the prompt before notifier;
    `--mock-claude` flag injecting fixture selection for scheduler tests.
  - Acceptance criteria: on the dev machine (Max sub): `python run_digest.py --dry-run`
    completes fetch→Claude→validated selection→printed digest with zero manual input; a
    deliberately broken selection fixture fails validation with a named reason; limit-hit
    text in mocked claude output → notifier path taken.
  - Test gate: `pytest tests/test_wrapper.py` (mocked subprocess) green + one real
    `run_digest.py --dry-run` live run on dev machine producing a valid digest from today's
    news (manual eyeball: items are real, summaries grounded, ≤8 items).
  - Depends on: Slices 1, 2. **Done is provisional**: the dev machine uses interactive
    login, a different auth/tooling path than the cloud runs — sandbox parity is only
    confirmed by Slices 4–5 (RND §Theme B).

### Milestone 2 — Cloud deployment & ops

- **Slice 4 — GitHub Actions fallback workflow**
  - Delivers: `.github/workflows/digest.yml` — cron `47 23 * * *` (=07:47 MYT, off-hour per
    RND) **commented out** + `workflow_dispatch` enabled; steps: checkout → pip install →
    `run_digest.py` (uses `CLAUDE_CODE_OAUTH_TOKEN`, `TELEGRAM_*` secrets; NOT `--bare`,
    NOT the action wrapper) → commit state w/ `[skip ci]` → failure step runs notifier.
    `concurrency` group, `timeout-minutes: 20`, `permissions: contents: write`.
  - Tasks (one subagent): workflow YAML incl. explicit git identity config
    (`git config user.name/user.email` before commit; push via `actions/checkout` default
    `GITHUB_TOKEN` — confirmed sufficient with `permissions: contents: write`); README
    section: secrets to set, how to flip cron on. Repo creation/push is **Checkpoint B**
    (explicit prerequisite, not a task footnote).
  - Acceptance criteria: `workflow_dispatch` run with `--mock-claude` + `--dry-run` (no
    secrets needed) goes green on GitHub **including the state-commit step**; with secrets
    present a real dispatch produces a Telegram message.
  - Test gate: green mock dispatch run on GitHub + `actionlint`/YAML validation locally;
    **token soak test**: real dispatch with `CLAUDE_CODE_OAUTH_TOKEN` at T0 and again at
    T0+48h both authenticate (settles the 1-year-vs-24h conflict from RND empirically —
    runs in background while Slices 5–6 proceed; fallback not declared usable until green).
  - Depends on: Slice 3, Checkpoint B.

- **Slice 5 — Routine setup + live validation (primary scheduler)**
  - Delivers: the daily Routine (Sonnet, daily 8:00 MYT, prompt: "Execute the daily digest:
    follow RUNBOOK.md in this repository exactly. Do not improvise beyond it.") on the
    user's account; environment network access set (start Full, tighten later per RND);
    `TELEGRAM_*` as environment variables; a "Run now" validation producing a real Telegram
    digest + state commit pushed back.
  - Tasks (commander-led, not subagent — touches the user's account): create via `/schedule`
    or hand the user a 5-step web-UI checklist; verify push-back behavior (RND flagged
    push-to-main as needs-validation; fallback: routine pushes `claude/state` branch and
    the Actions workflow or next run merges it — decide on observed behavior).
  - Acceptance criteria: one full unattended "Run now" cycle: digest arrives in Telegram,
    state commit visible in repo, run transcript shows RUNBOOK followed, no permission stalls.
  - Test gate: the live "Run now" itself + **3 consecutive daily scheduled runs** arriving
    within the stagger window (multi-day observation per RND unknowns; a 7-day watch
    continues post-handoff via README instruction).
  - Depends on: Slices 3, 4, Checkpoints A–C.

- **Slice 6 — Ops hardening + docs**
  - Delivers: README (architecture 1-pager; switch profile = 1-line config edit + commit;
    switch scheduler = pause routine / uncomment cron; annual `setup-token` refresh note;
    troubleshooting: no-digest-by-9am checklist); feed-health report line appended to digest
    footer when any feed was skipped stale/dead; weekend behavior (finance profile:
    Sat/Sun runs use lighter macro/gold framing — prompt rule in CLAUDE.md, not code).
  - Tasks (one subagent): README (must explicitly document the one failure class with no
    automated in-pipeline detection — "Routine never ran" — and its two mitigations:
    watchdog e-mail + no-digest-by-9am habit); footer logic + tests; CLAUDE.md weekend rule;
    **watchdog workflow** `.github/workflows/watchdog.yml`: daily cron ~10:30 MYT, checks
    latest commit touching `state/` is <26h old, fails otherwise → GitHub's native failure
    e-mail = Telegram-independent second alert channel (zero new infra).
  - Acceptance criteria: a stranger could operate the system from README alone; stale-feed
    day produces digest + one-line footer note rather than silence; watchdog goes red on a
    fixture-stale state and green on fresh state.
  - Test gate: `pytest` full suite green; watchdog dispatch test both directions; README
    walkthrough checklist self-audit.
  - Depends on: Slice 5.

`selection.json` schema (authoritative copy lives in CLAUDE.md):
`{"profile": str, "date": "YYYY-MM-DD", "items": [{"index": int, "summary": str,
"category": str?}], "skipped_as_repeat": [int]}` — 5–8 items, summaries ≤200 chars,
no URLs anywhere in model output.

## Risks & rollback

| Milestone | Risk | Rollback/mitigation |
|---|---|---|
| M1 | Feeds verified in RND rot by build time | fetch layer treats every feed as optional; Google News fallback query per profile; test gate includes dead-feed fixture |
| M1 | Sonnet returns malformed selection.json | schema validation + one retry with error appended, then notifier; `--mock-claude` keeps rest testable |
| M2/S4 | OAuth token behaves unlike docs (24h reports) | 48-h token soak test before relying on it; primary path (Routine) unaffected |
| M2/S5 | Routine can't push state to main | observed-behavior decision: `claude/state` branch + merge step; worst case state lives on branch permanently (dedup still works — fetcher reads that branch) |
| M2/S5 | Routines preview changes/breaks | flip to Actions fallback = uncomment cron + set secrets; scripts identical by design |
| Any | Digest silently absent | every failure path ends in notify_failure.py; watchdog workflow (S6) fails → GitHub e-mail when state stale >26h; README no-digest checklist |
| Any | Notifier shares Telegram creds with digest (SPOF) | accepted + engineered around: the watchdog e-mail channel is Telegram-independent and catches dead-creds and never-ran classes; documented in README as the designed second channel |

Rollback for any slice: git revert the slice's commits; slices are additive until S5.

## Definition of done (Phase 4 verifies against this)

- [ ] `pytest` suite green; every slice's test gate re-run and passing
- [ ] Live end-to-end on dev machine: real digest from today's news, dry-run and real send
- [ ] Real Telegram digest received from a cloud run (Routine "Run now")
- [ ] **3 consecutive** unattended scheduled runs arrive without human touch
- [ ] Profile switch demo: change config → next run reflects new profile
- [ ] Failure demo ×2: (a) pipeline failure (e.g. bad feed set) → Telegram alert arrives;
      (b) dead Telegram creds → watchdog goes red / GitHub e-mail fires (alert channel
      independence proven)
- [ ] No story repeated across two consecutive daily digests (state dedup observed working)
- [ ] Every digest link resolves (spot-check ≥5); zero model-authored URLs by construction
- [ ] README operable by a stranger; secrets documented; annual token-refresh note present;
      "Routine never ran" failure class + its two mitigations explicitly documented
- [ ] Actions fallback: green mock dispatch; 48-h token soak test green; cron
      documented-but-disabled
